# Firefox Realestate Importer

Расширение для Firefox (Manifest V3). Оно загружает страницу Zonaprop в браузере, получает объявления из DOM, затем последовательно открывает каждую карточку в фоновой вкладке. Данные собираются в JSON, который можно скачать или отправить в Laravel.

## Установка в Firefox

1. Откройте `about:debugging#/runtime/this-firefox`.
2. Нажмите **Загрузить временное дополнение / Load Temporary Add-on**.
3. Выберите `firefox-realestate-importer/manifest.json`.
4. Откройте иконку дополнения и нажмите **Открыть панель во вкладке**, чтобы видеть ход длительного сбора, не закрывая панель.
5. Откройте выдачу Zonaprop или **страницу отдельного объявления**: текущий URL автоматически появится в поле. Тип страницы определяется по URL для интерфейса, а при сборе дополнительно проверяется по DOM.
6. Если URL страницы или API отсутствует, расширение покажет ошибку с названием конкретного поля вместо ошибки конструктора URL. URL Laravel API и API-токен сохраняются автоматически при вводе в локальном хранилище Firefox и восстанавливаются при следующем запуске. На странице объявления нажмите **Импортировать объект в Laravel** — он будет собран и отправлен одним действием. На странице выдачи можно нажать **Собрать JSON**, затем **Скачать JSON**, либо сразу **Собрать и отправить в Laravel**.

После перезапуска Firefox временное дополнение потребуется загрузить снова. Для постоянной установки требуется подписанная сборка XPI (Firefox Add-ons/AMO либо корпоративный механизм установки).

## Laravel

В `.env` задайте уникальный случайный токен (не коммитьте его в Git):

```dotenv
PROPERTY_IMPORT_TOKEN=<random-long-private-value>
PROPERTY_IMPORT_IMAGE_HOSTS=imgar.zonapropcdn.com
```

Запустите:

```bash
php artisan migrate
php artisan config:clear
php artisan storage:link
php artisan route:list --path=api/realestate
php artisan test --filter=RealestateImportTest
```

Endpoint: `POST https://YOUR_DOMAIN/api/realestate/import`, заголовки `Authorization: Bearer ...`, `Content-Type: application/json`.

Пример:

```json
{
  "items": [
    {
      "source_platform": "zonaprop",
      "source_url": "https://www.zonaprop.com.ar/propiedades/clasificado/ejemplo-123.html",
      "title": "Casa en Pinamar",
      "country": "Argentina",
      "region": "Buenos Aires",
      "city": "Pinamar",
      "land_area": 615,
      "covered_area": 135,
      "semi_covered_area": 20,
      "currency": "USD",
      "price": 215000,
      "photos": []
    }
  ]
}
```

API принимает 1–5 объектов в одном запросе. Расширение отправляет по одному, чтобы показывать прогресс и ошибки каждого. Все новые объекты создаются со значением `active=false`; `newbuild=false`, `sold=false`. `source_url` — единственный внешний ключ, из URL убираются query-параметры. Дубли обновляются, а вручную опубликованные объекты сохраняют свои исправленные данные и `active=true`.

Географические Country → Region → City → District создаются автоматически, если для них хватает информации. Фотографии хранятся в коллекции `photos` Spatie Media Library, первая фотография также копируется в `cover`. Поддерживаются JPEG, PNG и WebP, максимум 15 МБ на фото и 40 фотографий на объект. Разрешённые хосты изображений задаются через `PROPERTY_IMPORT_IMAGE_HOSTS`.

## Ограничения и контроль качества

- В режиме выдачи сканируется **только одна переданная страница**. Следующие страницы указываются отдельно. В режиме отдельного объявления импортируется **один объект** без этапа выдачи.
- Если Zonaprop изменит DOM или выдаст блокировку, конкретная запись останется в JSON с `incomplete=true`; такая запись не отправляется на API.
- Галереи могут загружать полные фотографии только по действию пользователя: расширение собирает доступные в DOM URL и при необходимости дополняет их фотографиями из карточки выдачи. Проверьте количество и качество фото.
- География считывается из встроенной иерархии Zonaprop (`PAIS`, `PROVINCIA`, `CIUDAD`, `BARRIO`). Если дерево отсутствует, используется адрес. Для Capital Federal сохраняются `region=Capital Federal`, `city=Buenos Aires`, `district=Recoleta` (если район указан в источнике). Повторный импорт исправит связи неопубликованных объектов, но уже созданные ошибочные города сами не удаляются.
- Данные `m² tot.` не записываются в `total_area`. Из описания детальной страницы извлекаются `land_area`, `covered_area`, `semi_covered_area`.
- Расширение не выставляет `sold` и `newbuild` по косвенным признакам. После импорта проверьте объекты в Filament и публикуйте вручную.
- URL выдачи, Laravel API endpoint и API-токен сохраняются без срока истечения в `browser.storage.local`. При открытии расширения на странице Zonaprop её текущий URL имеет приоритет над предыдущим. В отдельной вкладке расширения используется последний сохранённый URL. Локальный токен хранится без шифрования и доступен расширению/профилю Firefox: используйте доверенный профиль, не синхронизируйте его в чужие устройства и удалите расширение/его данные, чтобы очистить токен.
- Используйте сбор данных и изображений только там, где разрешено партнёром и условиями источника.

Проверка расширения: `node --test firefox-realestate-importer/tests/*.test.cjs`.

Файлы: `parser.js` — извлечение DOM; `background.js` — обход ссылок и отправка; `popup.html` / `popup.js` — интерфейс расширения.


## Защита от зависания (1.0.5)

- Каждый запрос к Laravel ограничен 120 секундами. Если ответ не получен, ошибка показывается для конкретного `source_url`, и импорт остальных объектов продолжается.
- **Остановить** прерывает активный `fetch` через `AbortController`, а также ожидание загрузки Zonaprop, паузы и повторные попытки. Уже собранный JSON и результаты предыдущих объектов сохраняются.
- Если Firefox перезапустил MV3 background script посреди задачи, старый статус `running` сбрасывается в `Прервано`. После этого импорт можно запустить заново.
- Ошибки HTTP 422 (валидация) и JSON-ошибки API показываются явно, а не засчитываются как успешный импорт.
- Если HTTP-запрос отменён или истёк тайм-аут, Laravel **может продолжать** обработку уже принятого запроса. Повторный запуск безопасен благодаря дедупликации по `source_url`.
- Для диагностики серверных ошибок установите `opcodesio/log-viewer` и откройте `/log-viewer` (доступ только пользователю с ID 1). На сервере после `git pull` запустите `composer update opcodesio/log-viewer -W` и `php artisan log-viewer:publish`. Lock-файл создаётся Composer; не выполняйте только `composer install` со старым lock-файлом.

## Фоновые фотографии (очередь Laravel)

API сразу сохраняет объект и возвращает его ID и `photos_queued`. Каждая фотография загружается отдельной задачей `App\Jobs\ImportRealestatePhoto` в очереди `realestate-photos` через драйвер `database`. Ошибки CDN фиксируются в логах как предупреждения и не задерживают импорт следующих объектов. Поле `photos_added` теперь равно 0, поскольку фотографии обрабатываются позже.

**Для фотографий обязательно нужен постоянно запущенный queue worker** (Supervisor или systemd):

```bash
php artisan migrate --force
php artisan queue:work database --queue=realestate-photos --timeout=70 --tries=1 --sleep=3
```

Команда `php artisan queue:restart` перезапускает старые воркеры при обновлении кода. Пока worker не запущен, задания на скачивание остаются в таблице `jobs`, а на новом объекте фотографии могут временно отсутствовать.

Проверка: `php artisan test --filter=RealestateImportTest`. Повторный импорт использует `source_url` и не скачивает уже существующие медиа повторно.
